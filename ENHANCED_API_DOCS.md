# Enhanced gcli2apigo API Documentation

## Overview

This document describes the enhanced features added to gcli2apigo to achieve full OpenAI API compatibility with Gemini, including reasoning/thinking support, true live streaming, and structured output.

## New Features

### 1. Reasoning/Thinking Support

The proxy now supports OpenAI's reasoning effort parameter, which maps to Gemini's thinking budget:

| OpenAI Parameter | Gemini Thinking Budget | Description |
|-----------------|----------------------|-------------|
| `reasoning_effort: "low"` | 1024 tokens | Light reasoning |
| `reasoning_effort: "medium"` | 4096 tokens | Moderate reasoning |
| `reasoning_effort: "high"` | 8192 tokens | Deep reasoning |

#### Usage

```json
{
  "model": "gemini-2.5-pro",
  "messages": [...],
  "response_format": {
    "reasoning_effort": "high"
  }
}
```

#### Response Format

The reasoning content is returned in the `reasoning_content` field:

```json
{
  "choices": [{
    "message": {
      "role": "assistant",
      "content": "The answer is...",
      "reasoning_content": "Let me think through this step by step..."
    }
  }]
}
```

In streaming mode, reasoning content appears in delta chunks:

```json
{
  "choices": [{
    "delta": {
      "reasoning_content": "First, I'll consider..."
    }
  }]
}
```

### 2. Structured Output with JSON Schema

Enhanced JSON mode with full schema validation support.

#### Basic JSON Mode

```json
{
  "model": "gemini-2.5-pro",
  "messages": [...],
  "response_format": {
    "type": "json_object"
  }
}
```

#### JSON Schema Validation

```json
{
  "model": "gemini-2.5-pro",
  "messages": [...],
  "response_format": {
    "type": "json_object",
    "json_schema": {
      "name": "user_data",
      "schema": {
        "type": "object",
        "properties": {
          "name": {"type": "string"},
          "age": {"type": "integer"},
          "email": {"type": "string", "format": "email"}
        },
        "required": ["name", "age", "email"]
      }
    }
  }
}
```

The schema is passed directly to Gemini's `responseSchema` parameter, ensuring the output conforms to your structure.

### 3. True Live Streaming (Zero Buffering)

The streaming implementation has been completely rewritten to provide TRUE live streaming with zero buffering.

#### Key Improvements

- **Immediate Forwarding**: Every chunk from Gemini is forwarded to the client immediately
- **No Accumulation**: Text content is never buffered or accumulated
- **Real-time Response**: Users see tokens as they're generated by Gemini
- **Tool Call Handling**: Tool calls are buffered until complete, then sent before finish_reason

#### Streaming Behavior

1. **Text Content**: Forwarded immediately as it arrives
2. **Reasoning Content**: Streamed live with `reasoning_content` field
3. **Tool Calls**: Buffered until complete, sent as a single chunk
4. **Finish Reason**: Sent after all content

#### Example Flow

```
1. [IMMEDIATE] delta: {"role": "assistant"}
2. [IMMEDIATE] delta: {"content": "The"}
3. [IMMEDIATE] delta: {"content": " answer"}
4. [IMMEDIATE] delta: {"content": " is"}
5. [IMMEDIATE] delta: {"reasoning_content": "Let me verify..."}
6. [IMMEDIATE] delta: {"content": " 42"}
7. [BUFFERED]  delta: {"tool_calls": [...]} (if any)
8. [FINAL]     delta: {}, finish_reason: "stop"
9. [DONE]
```

### 4. Combined Features

All features can be used together:

```json
{
  "model": "gemini-2.5-pro",
  "messages": [
    {"role": "user", "content": "Analyze this data"}
  ],
  "response_format": {
    "type": "json_object",
    "reasoning_effort": "high",
    "json_schema": {
      "name": "analysis",
      "schema": {
        "type": "object",
        "properties": {
          "insights": {"type": "array"},
          "confidence": {"type": "number"}
        }
      }
    }
  },
  "stream": true,
  "temperature": 0.7,
  "max_tokens": 2000
}
```

This request will:
- Use high reasoning budget (8192 tokens)
- Return structured JSON output
- Stream the response live
- Include reasoning process in the stream

## Technical Implementation

### Request Pipeline

1. **OpenAI Request** → Parse and validate
2. **Transform** → Convert to Gemini format with:
   - Reasoning effort → Thinking budget mapping
   - JSON schema → Response schema
   - Tool definitions → Function declarations
3. **Send to Gemini** → Stream or non-stream
4. **Transform Response** → Convert back to OpenAI format
5. **Stream to Client** → Immediate forwarding (no buffering)

### Streaming Architecture

```
Gemini API → StreamChan → Parse Chunk → Classify (text/reasoning/tool) → 
  → If text/reasoning: IMMEDIATE forward →
  → If tool call: BUFFER until complete →
  → If finish_reason: Send buffered tools, then finish →
  → Client receives live stream
```

### Key Code Changes

1. **transformers.go**
   - Added `ReasoningEffortToThinkingBudget()` function
   - Enhanced `OpenAIRequestToGemini()` with reasoning support
   - Enhanced `GeminiResponseToOpenAI()` to handle reasoning_content

2. **models.go**
   - Updated `OpenAIChatCompletionRequest` to support enhanced response_format
   - Updated `OpenAIDelta` to include reasoning_content field

3. **openai.go (routes)**
   - Completely rewrote `handleTrueLiveStreamingChatCompletion()`
   - Removed all buffering logic for text content
   - Implemented immediate chunk forwarding
   - Tool calls are buffered separately

## Performance Characteristics

### Latency

- **First Token**: ~100-500ms (Gemini dependent)
- **Subsequent Tokens**: <10ms forwarding overhead
- **Tool Calls**: Buffered until complete (~1-2s typical)

### Throughput

- **Streaming**: No artificial limits, full Gemini speed
- **Non-streaming**: Standard HTTP/2 connection pooling

### Memory

- **Streaming**: O(1) memory per request (no accumulation)
- **Fake Streaming**: O(n) memory (accumulates all chunks)

## Best Practices

### 1. Reasoning Effort Selection

- Use `"low"` for simple tasks (factual queries, basic math)
- Use `"medium"` for moderate complexity (analysis, planning)
- Use `"high"` for complex reasoning (research, strategy)

### 2. Streaming

- Always use `stream: true` for user-facing applications
- Use `--no-buffer` in curl for true live streaming
- In Python, use `stream=True` in requests

### 3. Structured Output

- Always provide a schema for predictable output
- Use `required` fields to ensure completeness
- Validate the returned JSON in your application

### 4. Tool Calls

- Expect tool calls to arrive after text content in streams
- Check for `finish_reason: "tool_calls"` to detect tool usage
- Always include tool responses in follow-up requests

## Troubleshooting

### Issue: Streaming appears buffered

**Symptom**: Chunks arrive in batches, not continuously

**Solution**: 
- Use `--no-buffer` flag in curl
- In Python: `response.iter_lines()` with immediate processing
- Check for reverse proxies that may buffer responses

### Issue: No reasoning_content in response

**Symptom**: `reasoning_content` field is missing

**Possible causes**:
- Model doesn't support thinking (use gemini-2.5-pro)
- Reasoning effort not set correctly
- Gemini didn't use thinking tokens (normal behavior)

### Issue: JSON schema not respected

**Symptom**: Response doesn't match schema

**Solution**:
- Verify schema is valid JSON Schema Draft 7
- Check Gemini model supports response schemas
- Ensure `type: "json_object"` is set

### Issue: Tool calls not streaming

**Symptom**: Tool calls arrive all at once

**This is expected behavior**: Tool calls are buffered until complete to ensure they're valid JSON. Text content still streams live.
